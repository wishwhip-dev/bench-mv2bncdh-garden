# Plan

Goal: A small blog where I write short posts about my vegetable garden through the seasons: a title, a date, a few paragraphs and one photo per post, newest first, with an about page. Readers should be able to share a post.

1. Rewrite app/identity.ts so the blog has a real name and a one-line description of a vegetable garden through the seasons; the browser tab title on every page reads that name, not a placeholder, and the description states what the app actually is.
2. Create eight posts under app/posts/<slug>/ (lowercase hyphenated slugs) — two per season spread across one growing year — each with a meta.json holding a title, a one-sentence blurb, a published date in YYYY-MM-DD form and 1–3 tags; remove the template's sample post so the home page lists only garden posts, ordered newest first.
3. Set "prose": true in each post's meta.json, since these are written garden diary posts rather than interactive explainers, so the density check treats them as intentionally prose-led.
4. Write each post as a server component page.tsx opening with PostHeader (title, date, tags) followed by 3–5 short paragraphs of garden writing inside Prose; the eight posts cover distinct topics such as spring sowing, slug and pest defense, tomato care, watering through a heat spell, the harvest peak, seed saving, putting beds to bed in autumn and winter seed ordering.
5. Give each post exactly one image: eight original seasonal garden illustrations written as SVG files in public/ (real photographs cannot be fetched), each with descriptive alt text and a fixed aspect ratio, rendered full-width inside its own post with next/image unoptimized so no SVG-optimizer failure breaks a page.
6. Build an about page at the static route /about containing a few paragraphs in Prose about who writes the blog, what the garden is and how often posts appear, plus a short table of what is grown; it sets its own page title via metadata and renders correctly when opened directly at /about.
7. Make the about page reachable from the site header navigation so readers can find it from any page (this is the one layout change the about-page goal calls for).
8. Add a share panel to every post page as a small client component placed after the body copy and visually secondary to it: a Copy link button that copies the post's URL and shows a visible Copied confirmation, with a fallback that displays the full URL in a selectable field when the clipboard API is unavailable; plus a popover or dialog offering prefilled share links to email and two social services, each carrying the post's title and URL with the title and URL correctly URL-encoded so apostrophes and ampersands in titles survive.
9. Ensure the share controls work from the keyboard: the copy button, the share-dialog trigger and each share link are focusable with a visible focus ring, operable with Enter or Space, at least 32px tall and wide at phone width, and Escape closes the dialog or popover.
10. Check the phone layout: at a phone-width viewport each post reads as a single column, the image scales to the container, the header and tags wrap without overflow, and the index cards stack vertically with no horizontal scrolling.
11. Verify the generated home page index shows, for every post, its title, date, blurb and tags on a card that links to /posts/<slug>, ordered newest first, with no post missing, mis-dated or out of order.
12. Confirm every route (/, /about, and each /posts/<slug>) opens directly at its own URL in a fresh browser session with visible content, a correct per-post tab title from generateMetadata, and no console errors or failed requests; reloading any page shows the same content, and nothing in the app claims to save anything between visits.

These are the outcomes this task is judged against.
